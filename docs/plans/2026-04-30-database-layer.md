# Milestone 2: Database Layer — Implementation Plan

**Goal:** Wire up `tauri-plugin-libsql` on the Rust side and Drizzle ORM with sqlite-proxy on the frontend, with migrations run on app startup.

**Architecture:** Use `tauri-plugin-libsql` (by huakunshen) which provides a Tauri plugin that executes SQL via libsql. On the frontend, `drizzle-orm/sqlite-proxy` serializes queries as SQL+params, sent via Tauri's `invoke()` to the plugin. Migrations are generated by `drizzle-kit`, bundled by Vite's `import.meta.glob`, and run via the plugin's browser-safe `migrate()` function on app startup. The plugin handles everything — no custom Tauri commands needed.

**Tech Stack:** `tauri-plugin-libsql` v0.1.0 (Rust), `tauri-plugin-libsql-api` (JS), `drizzle-orm`, `drizzle-kit`

### Task 2: Register the plugin in lib.rs with app data dir

**Files:**
- Modify: `src-tauri/src/lib.rs`

**Step 1: Register the plugin**

Replace the entire `lib.rs` with:

```rust
use tauri::Manager;

#[cfg_attr(mobile, tauri::mobile_entry_point)]
pub fn run() {
    tauri::Builder::default()
        .plugin(tauri_plugin_opener::init())
        .plugin(tauri_plugin_safe_area_insets_css::init())
        .setup(|app| {
            let data_dir = app
                .path()
                .app_data_dir()
                .expect("failed to resolve app data dir");

            std::fs::create_dir_all(&data_dir).expect("failed to create app data dir");

            let config = tauri_plugin_libsql::Config {
                base_path: Some(data_dir),
                encryption: None,
            };

            app.handle()
                .plugin(tauri_plugin_libsql::init_with_config(config))?;

            Ok(())
        })
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}
```

This sets `base_path` to the Tauri `app_data_dir` so the database file persists at the correct platform-specific location. On Android this is the app's internal storage. On desktop it's `~/.local/share/com.sakti-dev.sakti-pos/`.

The plugin is registered inside `.setup()` because `init_with_config` needs the app handle, and we need `app.path()` to resolve the data directory. We also `create_dir_all` to ensure the directory exists before the DB tries to write to it.

Note: No `greet` command — it was removed in Milestone 1. No `use std::path::PathBuf` needed since we pass the `PathBuf` returned by `app_data_dir()` directly.

### Task 5: Create Drizzle schema

**Files:**
- Create: `src/db/schema.ts`

**Step 1: Write the schema**

```typescript
import { sqliteTable, text, integer } from "drizzle-orm/sqlite-core";

export const users = sqliteTable("users", {
  id: integer("id").primaryKey({ autoIncrement: true }),
  name: text("name").notNull(),
  pin: text("pin").notNull(),
  role: text("role", { enum: ["owner", "manager", "cashier"] }).notNull(),
  isActive: integer("is_active", { mode: "boolean" }).notNull().default(true),
  createdAt: text("created_at").notNull().$defaultFn(() => new Date().toISOString()),
  updatedAt: text("updated_at").notNull().$defaultFn(() => new Date().toISOString()),
});

export const categories = sqliteTable("categories", {
  id: integer("id").primaryKey({ autoIncrement: true }),
  name: text("name").notNull(),
  sortOrder: integer("sort_order").notNull().default(0),
  isActive: integer("is_active", { mode: "boolean" }).notNull().default(true),
  createdAt: text("created_at").notNull().$defaultFn(() => new Date().toISOString()),
  updatedAt: text("updated_at").notNull().$defaultFn(() => new Date().toISOString()),
});

export const products = sqliteTable("products", {
  id: integer("id").primaryKey({ autoIncrement: true }),
  categoryId: integer("category_id").references(() => categories.id),
  name: text("name").notNull(),
  price: integer("price").notNull(),
  imageUrl: text("image_url"),
  isActive: integer("is_active", { mode: "boolean" }).notNull().default(true),
  sortOrder: integer("sort_order").notNull().default(0),
  createdAt: text("created_at").notNull().$defaultFn(() => new Date().toISOString()),
  updatedAt: text("updated_at").notNull().$defaultFn(() => new Date().toISOString()),
});

export const orders = sqliteTable("orders", {
  id: integer("id").primaryKey({ autoIncrement: true }),
  orderNumber: text("order_number").notNull().unique(),
  userId: integer("user_id").references(() => users.id),
  total: integer("total").notNull(),
  paymentMethod: text("payment_method", { enum: ["cash", "qris"] }).notNull(),
  amountPaid: integer("amount_paid"),
  changeAmount: integer("change_amount"),
  status: text("status", { enum: ["completed", "cancelled"] }).notNull(),
  createdAt: text("created_at").notNull().$defaultFn(() => new Date().toISOString()),
  updatedAt: text("updated_at").notNull().$defaultFn(() => new Date().toISOString()),
});

export const orderItems = sqliteTable("order_items", {
  id: integer("id").primaryKey({ autoIncrement: true }),
  orderId: integer("order_id").references(() => orders.id).notNull(),
  productId: integer("product_id").references(() => products.id),
  productName: text("product_name").notNull(),
  quantity: integer("quantity").notNull(),
  unitPrice: integer("unit_price").notNull(),
  subtotal: integer("subtotal").notNull(),
  createdAt: text("created_at").notNull().$defaultFn(() => new Date().toISOString()),
});
```

Notes:
- `is_active` uses `integer({ mode: "boolean" })` because SQLite has no native boolean type
- `role` and `payment_method` use TypeScript enums via `text("col", { enum: [...] })` for type safety
- `price`, `total`, etc. are plain `integer` — all monetary values are whole IDR
- Foreign keys use `.references(() => table.id)` for Drizzle relations
- `$defaultFn` provides defaults at the Drizzle/JS level (not SQL-level defaults) for timestamps

**Step 2: Commit**

```bash
git add src/db/schema.ts
git commit -m "feat: add Drizzle schema for all 5 tables"
```

### Task 6: Create Drizzle client

**Files:**
- Create: `src/db/index.ts`

**Step 1: Write the client**

```typescript
import { drizzle } from "drizzle-orm/sqlite-proxy";
import { createDrizzleProxy } from "tauri-plugin-libsql-api";
import * as schema from "./schema";

const DB_PATH = "sqlite:sakti-pos.db";

export const db = drizzle(createDrizzleProxy(DB_PATH), { schema });

export type Database = typeof db;
```

Notes:
- `createDrizzleProxy(DB_PATH)` returns the `{ execute, batch }` callback pair that Drizzle's `sqlite-proxy` driver needs
- The proxy lazily loads the database on first use — no need to call `Database.load()` separately
- The path `sqlite:sakti-pos.db` is relative to the `base_path` we configured in Rust (the app data dir)

### Task 9: Wire migrations into app startup

**Files:**
- Modify: `src/index.tsx`

**Step 1: Update the entry point**

Replace `src/index.tsx` with the bootstrap sequence:

```typescript
/* @refresh reload */
import "@saurl/tauri-plugin-safe-area-insets-css-api";
import { render } from "solid-js/web";
import { Database, migrate } from "tauri-plugin-libsql-api";
import App from "./App";
import { initSafeArea } from "./lib/safe-area";
import "./index.css";

const root = document.getElementById("root");

if (import.meta.env.DEV && !(root instanceof HTMLElement)) {
  throw new Error(
    "Root element not found. Did you forget to add it to your index.html? Or maybe the id attribute got misspelled?",
  );
}

const DB_PATH = "sqlite:sakti-pos.db";

const migrations = import.meta.glob<string>("../drizzle/*.sql", {
  eager: true,
  query: "?raw",
  import: "default",
});

async function bootstrap() {
  initSafeArea();

  try {
    await Database.load(DB_PATH);
    await migrate(DB_PATH, migrations);
  } catch (err) {
    console.error("Failed to initialize database:", err);
  }

  render(() => <App />, root!);
}

bootstrap();
```

Notes:
- `import.meta.glob("../drizzle/*.sql", ...)` — Vite bundles the SQL file contents into the JS at build time. The `?raw` query param returns file contents as strings. The path `../drizzle/*.sql` is relative to `src/index.tsx`.
- `Database.load()` must be called before `migrate()` — the plugin needs an open connection.
- `migrate()` creates a `__drizzle_migrations` tracking table and runs only pending migrations.
- The entire app bootstrap is async — migrations complete before the UI renders.
- Error handling: if DB init fails, we log the error but still render the app (graceful degradation).
- DEV-mode root element check from the original Tauri scaffold is restored.

## Key decisions

- **No encryption** — disabled via `default-features = false, features = ["core"]`. Not needed for v1.
- **No seed data yet** — deferred to Milestone 3 (auth) so we can properly hash the PIN with bcrypt.
- **`import.meta.glob` for migrations** — browser-safe, no filesystem access needed at runtime.
- **Plugin registered in `.setup()`** — required because `init_with_config` needs app handle for `app_data_dir`.
- **`create_dir_all` before DB init** — ensures the data directory exists on first launch.
- **Graceful error handling in bootstrap** — DB init failure is logged but app still renders.
